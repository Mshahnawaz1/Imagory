# Imagory website

The public site for [Imagory](https://github.com/Mshahnawaz1/imagory), built with Astro 7 as a
static site. It has the home page, docs, changelog, privacy notice, download pages and a 404
page. It lives in `frontend/` of the main repository and has no server code.

Imagory itself is an offline app. The site is the only part that uses analytics (Vercel Web
Analytics, cookieless). The app makes no network connections.

## Commands

Run these from `frontend/`. Node 22 or newer is required.

```sh
npm ci              # install exact dependencies from package-lock.json
npm run dev         # local dev server
npm run build       # static build into dist/
npm run preview     # serve dist/ locally
npm run check       # astro check (types and template errors)
node scripts/make-og.mjs   # regenerate public/og.png (1200x630)
```

## Structure

```
src/site.ts              version, download file names, nav and footer links
src/pages/               routes (index, docs, changelog, privacy, download/[os], 404)
src/layouts/             Base (head, header, footer, analytics) and Docs
src/components/          shared components
src/content/docs/        docs pages (Markdown)
src/content/changelog/   one file per release, named <version>.md
src/assets/screenshots/  screenshots, made from a synthetic library
src/styles/              tokens (colours, type) and global styles
public/                  favicon, og.png, robots.txt
scripts/make-og.mjs      renders the Open Graph image
vercel.json              clean URLs and cache headers for /_astro/*
design.md, todo.md       plan and work tracker
```

## Releasing a version

1. Edit `release` in `src/site.ts`: `version`, `tag` (for example `v0.3.0`) and `date`.
   If the file names change, update `downloads` too.
2. Add `src/content/changelog/<version>.md`.
3. Publish the GitHub release with the same tag. The asset names must match exactly:
   `Imagory.exe` and `Imagory-<version>-linux-x86_64.tar.gz`. The download buttons link to
   these files directly, so a mismatch gives a 404.
4. Push. Vercel rebuilds the site.

## Screenshots

Screenshots come from a synthetic library generated by the tools in the app repository.
Never use real photos, and never commit them.

## Deploying on Vercel

1. Import the GitHub repository and set **Root Directory** to `frontend`.
2. Framework preset: **Astro**. Build command `npm run build`, output `dist`.
3. **Ignored Build Step:** `git diff HEAD^ HEAD --quiet -- .`. Commits that only change the
   Python app then don't rebuild the site.
4. Turn on **Web Analytics** in the project settings.

### Domain

1. In Vercel, add `imagory.mshahnawaz.me` to the project.
2. At the DNS provider for `mshahnawaz.me`, add a record:
   `CNAME imagory → cname.vercel-dns.com`.
3. Vercel issues the HTTPS certificate once DNS resolves.
